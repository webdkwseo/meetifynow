# MeetifyNow — Kryteria akceptacji

## Globalne zasady akceptacji
- Każda funkcja musi mieć jasny outcome biznesowy.
- Każdy przepływ krytyczny musi mieć stan pusty, loading, success i error.
- Każda zmiana w UI ma ograniczać tarcie, a nie dodawać konfigurację bez potrzeby.
- Agent nie może zakładać nazw tabel, kolumn ani endpointów bez inspekcji repo.

## Faza 1 — Scheduling Core
### Akceptacja
- użytkownik tworzy wydarzenie bez nadmiarowych pól,
- uczestnik odpowiada przez link bez tworzenia konta,
- organizator widzi czytelny obraz odpowiedzi,
- finalizacja terminu jest jednoznaczna,
- potwierdzenia są wysyłane poprawnie,
- strefy czasowe nie wprowadzają konfliktów.

## Faza 2 — Team Workflow
### Akceptacja
- workspace ma czytelny onboarding,
- rola i uprawnienia są zrozumiałe z poziomu UI,
- przypomnienia działają bez ręcznej ingerencji,
- dashboard pokazuje minimalny zestaw sensownych metryk,
- branding nie psuje czytelności produktu.

## Faza 3 — Growth Layer
### Akceptacja
- integracje nie wymagają niejasnych kroków,
- rekomendacje slotów są wyjaśnialne dla użytkownika,
- recurring flows skracają czas tworzenia podobnych spotkań,
- analityka wspiera decyzje, nie jest dekoracją.
